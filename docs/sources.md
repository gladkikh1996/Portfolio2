## Почему файлы собирались отдельно

Ранние merge request’ы иногда удаляли предыдущие упражнения. Семь ещё открытых MR дополнительно удаляют файлы коллекций, которые должны остаться в портфолио. Поэтому сборка переносит выбранные решения в независимые каталоги, не сливая целиком исходные ветки. Одинаковые имена `oop.py`, `main.py` и локальных модулей не конфликтуют.

Новая Git-история начинается со сборки портфолио. Она не имитирует даты и последовательность исходной разработки. Первый коммит импорта — `02a0e3aabcc06bbd52cfd396ed2466acb5dc63e8`; все 37 файлов в нём совпадают с полученными исходниками.

Для каждого файла [source-manifest.json](source-manifest.json) содержит каталог назначения, исходную ветку, SHA коммита-снимка, исходное имя и ссылку на файл. Поля `sha256` и `bytes` описывают исходную версию при импорте и не изменяются после исправлений. Только у двух исправленных файлов добавлены `portfolio_sha256` и `portfolio_bytes` для текущей версии, а также `modification` с описанием изменения. Если этих полей нет, текущий файл совпадает с исходной версией. Поле `original_import_commit` указывает коммит для проверки исторических хешей. Локальные пути компьютера и данные входа в манифест не включены.

Добавленные при оформлении файлы: README, документы в `docs/`, корневые `.gitignore` и `.gitattributes`. После публикации по запросу автора исправлены `data_types.py` и `set_task.py`: ожидаемые `TypeError` и `KeyError` теперь обработаны с пояснением, чтобы выполнение доходило до последнего упражнения. Учебный смысл демонстраций сохранён; остальные исходные файлы не изменялись. Лицензия на учебные материалы здесь не назначается автоматически.
